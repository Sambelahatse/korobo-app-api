# KOROBO APP API

Express + TypeScript API for KOROBO APP. PostgreSQL stores app data and user profiles. Authentication is issued by this API; Supabase Auth is not used.

## Custom JWT authentication

- Access JWT: HS256, 15 minutes by default.
- Refresh token: random opaque token stored only as a SHA-256 hash in `public.auth_sessions`; browser receives it as an HttpOnly cookie.
- Refresh tokens rotate after every successful refresh.
- Passwords are hashed with bcrypt (12 rounds).
- User UUIDs are preserved to keep existing foreign-key references intact.
- Password setup links are single-use and expire after 48 hours.

## Required environment

Set these in Render before deploying the authentication PR:

- `DATABASE_URL`: PostgreSQL connection string.
- `JWT_SECRET`: a randomly generated secret with at least 32 characters; never expose it to the frontend.
- `CORS_ORIGIN`: exact frontend origin, e.g. `https://korobo-app.onrender.com`.
- `COOKIE_SECURE=true` in production.
- `OWNER_BOOTSTRAP_TOKEN`: random value of at least 32 characters, used temporarily to prepare existing accounts for password setup.

Example secret generation: `openssl rand -base64 48`.

## Migration sequence — do not skip

1. Back up PostgreSQL before changing the schema.
2. Apply `migrations/1710000000000-CustomJwtAuth.ts` using the TypeORM migration runner, or apply its SQL statements in the database SQL editor.
3. Deploy the API and frontend changes together only after both CI checks pass.
4. Generate a one-time password setup link for each existing user using `POST /auth/migration/setup-link`, with header `x-owner-bootstrap-token: <OWNER_BOOTSTRAP_TOKEN>` and JSON body `{"email":"user@example.com"}`. This endpoint preserves the existing profile and role. Send the returned `setupUrl` to that user through a secure channel.
5. Each user opens the link and chooses a new password. Existing Supabase Auth password hashes cannot be exported or reused by this custom system.
6. After all existing users are migrated, remove `OWNER_BOOTSTRAP_TOKEN` from Render. Normal password setup links for future accounts can be generated by an authenticated admin through `POST /auth/password/setup-link`.
7. Automatic email delivery is not configured. The setup URL is returned once to the authorized caller and must be delivered manually until an email provider is integrated.

## Endpoints

- `POST /auth/login`
- `POST /auth/refresh`
- `POST /auth/logout`
- `GET /auth/me`
- `POST /auth/password/setup`
- `POST /auth/password/setup-link` (admin only)
- `POST /auth/migration/setup-link` (temporary migration token)
- `POST /auth/bootstrap-owner` (one-time owner setup)
- `POST /auth/invite` (admin only; returns a one-time setup URL)

## Development

```sh
bun install
bun run dev
bun run typecheck
bun test
```

Do not merge/deploy the draft authentication changes until the schema migration, production environment, password setup delivery, and end-to-end session tests are ready.
